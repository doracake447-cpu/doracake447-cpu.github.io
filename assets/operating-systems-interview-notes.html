Operating Systems Detailed Notes

Focus on concepts, trade-offs, and common interview explanations. In interviews, always mention why a design is used, not just definitions.

1) Fundamentals

An Operating System is a resource manager that provides abstractions over hardware and enables safe, efficient program execution.

  • Kernel mode vs User mode: privileged instructions execute only in kernel mode.
  • System call: controlled transition from user mode to kernel mode.
  • Interrupt: asynchronous event (I/O/device/timer) that preempts normal flow.
  • Trap/Exception: synchronous event caused by current instruction (e.g., divide-by-zero, page fault).
  • Context switch: saving and restoring CPU state to switch runnable tasks; pure overhead.
Interview tip: Mention that user mode improves security by preventing direct hardware access from applications.

2) Process vs Thread

PropertyProcessThread
Address spaceSeparateShared inside same process
Creation costHigherLower
CommunicationIPC neededShared memory naturally
Fault isolationStrongWeak (thread crash may kill process)

PCB (Process Control Block) stores PID, state, registers, program counter, scheduling info, memory pointers, open files.

Thread states: new, ready, running, blocked/waiting, terminated.

Concurrency vs Parallelism: concurrency is progress overlap; parallelism is simultaneous execution on multiple cores.

3) CPU Scheduling

Goal: maximize utilization and throughput, while minimizing waiting, turnaround, and response time.

AlgorithmTypeProsCons
FCFSNon-preemptiveSimple, fair by arrivalConvoy effect, poor response
SJFUsually non-preemptiveOptimal avg waiting timeNeeds burst estimate, starvation risk
SRTFPreemptive SJFGood response for short jobsHigh context-switch overhead

Round RobinPreemptiveGood interactive responseQuantum tuning sensitive

Formula reminders: Turnaround = Completion - Arrival, Waiting = Turnaround - Burst, Response = FirstRun - Arrival.

Interview tip: If asked about RR quantum, explain: too small means heavy context switches; too large behaves like FCFS.

4) Synchronization & Critical Section

Race condition: output depends on interleaving of concurrent operations.

Critical-section solution requirements:

  • Mutual exclusion
  • Progress
  • Bounded waiting

Mechanisms:

  • Mutex: lock/unlock primitive for exclusive access.
  • Semaphore: integer + wait(P)/signal(V); binary or counting.
  • Monitor + condition variables: higher-level structured synchronization.
  • Spinlock: busy-wait lock, useful for very short critical sections.

Classic problems to practice: Producer-Consumer, Readers-Writers, Dining Philosophers.

Difference: Mutex has ownership (locker unlocks). Semaphore generally does not enforce ownership.

5) Deadlocks

Deadlock: set of processes permanently waiting for each other.

Coffman conditions (all four required):

  • Mutual exclusion
  • Hold and wait
  • No preemption
  • Circular wait

Handling strategies:

StrategyIdeaExample
PreventionBreak one Coffman conditionResource ordering to avoid circular wait
AvoidanceAllocate only safe statesBanker's algorithm
Detection + RecoveryAllow, detect cycle, recoverKill process / preempt resource
IgnoreAssume rareMany general-purpose OS cases

6) Memory Management

Contiguous allocation leads to external fragmentation; paging solves external fragmentation.

Paging: logical memory split into pages, physical memory into frames. Address = page number + offset.

Segmentation: memory divided by logical units (code/data/stack), each with base and limit.

Fragmentation summary:

  • Internal fragmentation: wasted space inside allocated block/frame.
  • External fragmentation: free memory exists but is non-contiguous.

Page table acceleration uses TLB (Translation Lookaside Buffer), a small cache of page table entries.

7) Virtual Memory & Page Replacement

Virtual memory allows processes to run with partial memory residency using demand paging.

Page fault handling: trap -> validate reference -> locate page on disk -> load into free frame or replace victim -> update table -> restart instruction.

PolicyRuleNotes
FIFOEvict oldest loaded pageSimple, may show Belady's anomaly
LRUEvict least recently usedGood approximation of optimal
OptimalEvict farthest future useTheoretical benchmark only
Clock/Second-chanceUse reference bit to approximate LRUPractical in real systems

Thrashing: excessive page faults causing low CPU utilization. Mitigate by reducing multiprogramming level or using working-set / page-fault-frequency control.

8) File System & I/O

File systems map logical files to physical blocks and maintain metadata such as size, owner, permissions, timestamps.

  • Allocation methods: contiguous, linked, indexed.
  • Directory structures: single-level, two-level, tree, acyclic graph.
  • Access control: Unix permissions (rwx), ACLs.
  • I/O methods: programmed I/O, interrupt-driven I/O, DMA.
  • Disk scheduling: FCFS, SSTF, SCAN, C-SCAN.

Kernel buffering and caching improve throughput by reducing device wait and batching operations.

9) High-Frequency Interview Q&A

Q: Why are system calls slower than normal function calls?
A: They require user-kernel mode switch, validation checks, and possible scheduling/interrupt handling.
Q: Why are threads considered lightweight?
A: They share process resources (address space, files), so create/switch overhead is lower than process switching.
Q: Semaphore vs Mutex?
A: Mutex is ownership-based exclusive lock; semaphore is signaling/counting primitive and may allow non-owner signal in many implementations.
Q: Starvation vs Deadlock?
A: Starvation means indefinite postponement of one process; deadlock is circular waiting where none of involved processes can proceed.
Q: What is a zombie process?
A: A terminated child whose exit status is not yet collected by parent (wait() not called).
Q: What causes priority inversion?
A: Low-priority thread holding lock needed by high-priority thread while medium-priority thread runs; mitigation: priority inheritance.
